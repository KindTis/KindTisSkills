# Jira 요청 라우팅

요청에 맞는 지침을 한 번 선택한다. 업무 스킬과 `jira:status`는 동등한 독립 지침이며 실행 에이전트가 선택된 지침을 적용한다. 이 스킬은 실제 업무 수행·진행 조정·상태 반영이나 단계 보고 수신·결과 취합·복구를 담당하지 않는다.

## 요청과 지침 선택

현재 요청·기존 대화·프로젝트 지침에서 대상 Key/URL·프로젝트, 원하는 산출물과 승인 범위를 확인한다. 필요한 정보만 조회하고, 대상이나 핵심 요구를 유일하게 정할 수 없을 때만 확인한다. Key만 주어졌으면 실제 이슈 유형과 요청 목적을 확인해 단일 이슈 구현과 에픽 구성·실행을 구분한다. 선택한 경로에 필요한 지침만 현재 목록에서 찾아 읽는다.

| 요청 | 선택할 지침 |
| --- | --- |
| 이슈 조회·검색·설명, Jira 스킬 자체의 검토·편집 | 요청한 조회·설명·편집에 필요한 지침만. Jira 변경·개발 실행 지침은 추가하지 않음 |
| 작성된 명세로 새 이슈 발행 | `jira:spec-ticket` + `jira:status` |
| 기존 단일 Key 또는 목록·프로젝트의 아이디어 이슈 구체화·반영 | `jira:specify` + `jira:status` |
| 에픽·하위 명세와 이슈 구성·등록, 또는 에픽의 작업 배정·실행 | `jira:epic` + `jira:status` |
| 단일 이슈의 첨부 명세 구현·검증 | `jira:work` + `jira:status` |
| 확인된 실제 단계의 상태·댓글 반영만 | `jira:status` |
| 기존 이슈의 로컬 명세 준비만 | `jira:specify`의 명세 준비 범위 |
| 에픽 분해·로컬 명세 준비만 | `jira:epic`의 준비 범위 |

로컬 명세 준비·분해만 요청했으면 Jira 쓰기·상태 지침을 선택하지 않는다. 명세 작성·구체화 후 신규 발행까지 요청한 복합 요청은 `superpowers:brainstorming`을 요구 구체화·명세 작성/검토까지만 적용하는 지침으로 선택하고, 명세 승인 후의 Jira 발급에는 완성 명세 발급·상태 지침을 선택한다. 구현 계획 단계로 자동 진행하는 범위는 포함하지 않는다. '이 명세를 발행해'의 입력 누락·미완성은 부족한 점을 확인할 사유이며 새 명세 작성 승인으로 간주하지 않는다.

기존 에픽 실행은 현재 명세·하위·관계·순서를 확인하는 경로로 연결하며 재분해·재등록을 강제하지 않는다. 준비·등록만 요청했으면 그 범위를 유지하고 실행도 요청했으면 작업 배정까지 포함한다.

복합 요청은 승인된 단계와 의존 순서를 함께 명확히 한다. 발행·명세 보강만 요청받았으면 구현이나 작업 세션 실행을 추가하지 않고, 기존 이슈 구체화를 신규 발급으로 바꾸지 않는다.

## 직접 지정과 독립 실행

사용자가 업무 스킬과 `jira:status`를 명시했다면 그 조합을 그대로 사용한다. 업무 스킬 단독 지정에 `manage`나 상태 지침을 자동 추가하지 않는다. 지침 선택을 마치면 실행 에이전트가 해당 지침으로 작업하며 이 라우터로 단계 사실을 되돌려 보내지 않는다. 지침 선택 횟수는 실제 상태 변경 횟수를 제한하지 않으며 상태 정책과 적용 시점은 `status`에만 둔다.
