# Jira 이슈 작업 실행

개발 작업은 다음 지시로 수행한다.

> 첨부된 명세를 $improve:implement 스킬 지침에 따라 작업한다. 작업은 지시한 작업 공간에서 진행하고, 지시가 없으면 현재 브랜치에서 진행한다

이 스킬은 이슈·명세·저장소 연결과 실행 분기를 담당한다. 구현 절차는 `improve:implement`, 상태와 댓글은 `jira:status`에 맡긴다. 의존 스킬은 사용하는 단계에서 현재 목록으로 찾아 읽는다. 티켓 등록·단순 조회·명세 설명·스킬 편집 요청에는 개발을 시작하지 않는다.

## 대상과 실행 경로

현재 Jira 도구의 실제 스키마로 대상 Key/URL의 프로젝트·유형·본문·첨부·상태를 확인한다. 실제 유형으로 단일 이슈와 에픽을 구분하고, 에픽의 하위 목록은 부모·자식 관계로 조회한다.

- 기준 명세는 Description의 `Specification`이 지정한 첨부 Markdown이다. 누락·동명 중복 등으로 기준이 모호하면 확인하며, 최신 업로드나 본문 요약으로 대체하지 않는다.
- 명시된 저장소를 우선한다. 없으면 **Jira의 프로젝트명(스페이스명)이 Codex의 프로젝트 폴더와 동일**한 경로를 찾고, 후보가 없거나 여러 개일 때만 확인한다.
- 작업 범위와 저장소 지침을 확인한다. 재시도는 같은 이슈의 기존 실행·결과를 이어가며 중복 세션을 만들지 않는다.
- `명세 필요` 상태 티켓은 명세가 확정되지 않았으므로 개발을 시작하지 않고 그 사실을 알린다.

단일 이슈는 현재 주 에이전트 세션에서 아래 절차를 수행한다. 에픽은 현재 주 에이전트가 순서·입력·세션 실행을 조정하고 실제 개발은 독립 주 에이전트 세션이 담당한다. 각 주 에이전트는 자식을 직접 생성·호출하고, 역할과 Advisor 호출 조건은 전역 지침을 따른다.

## 단일 이슈 실행

1. 작업 위치는 사용자가 지시한 작업 공간으로 하고, 지시가 없으면 현재 브랜치로 한다. 계획·코드 변경 전에 작업 위치를 확정하고 기존 사용자 변경을 보존한다. worktree를 지시받았으면 `superpowers:using-git-worktrees`로 확보하되, worktree 폴더가 ignore되어 있지 않으면 `.gitignore` 대신 `.git/info/exclude`에 추가한다.
2. 지정 첨부를 불변 입력 명세로 작업 위치에 두고 위 지시로 `improve:implement`를 수행한다. 사용자에게 goal 실행도 요청받았다면 실제 goal로 등록하거나 일치하는 기존 goal을 사용한다. 다른 미완료 goal을 덮어쓰지 않는다.
3. 실제 단계와 결과를 `jira:status`에 전달하고, 구현 스킬의 개발·검증 결과와 남은 인수 항목을 반환한다.

첨부 원본은 보존하며 구현·검증은 구현 스킬의 절차를 따른다. 명세의 모순·누락으로 진행할 수 없으면 `jira:status`로 확인 요청을 남긴다. Jira 본문·첨부·분류의 변경이나 main/master 병합·푸시·배포·worktree 정리를 이 실행 지시만으로 추가하지 않는다.

## 에픽 실행

에픽 주 에이전트는 실행 순서·작업 간 의존성·세션 조정·코드 인계·결과 취합, 일반 실패 처리와 최종 완료 판단·처리를 담당한다. 각 작업의 주 에이전트는 해당 승인 범위의 독립 리뷰·구현·재작업·검증을 직접 위임·조정하고 최종 완료를 판단하며 완료까지 책임진다. 같은 범위의 재작업마다 상위 승인을 다시 요구하지 않는다. 작업 간 영향·범위 변경·스스로 해결할 수 없는 장애는 에픽 조정 주 에이전트에게 근거를 반환한다. 역할과 Advisor 호출 조건은 전역 지침을 따르며, 의존성의 설계 문제·중요한 구조 영향도 Advisor 자문 대상이다.

### 순서와 선행 결과

에픽 **Description의 실행 순서**를 실제 하위 Key와 대조한다. 순서 누락·충돌은 기존 대화로 확정할 수 없으면 확인한다. 이슈 번호나 생성일로 순서를 추측하지 않는다.

기본은 본문 순서에 따른 순차 실행이다. 명시된 병렬 그룹만 실제 의존성과 작업 공간이 분리되어 있을 때 병렬 실행한다. 에픽을 조정하는 세션은 개발용 의존 스킬을 미리 읽을 필요 없이 필요한 입력을 실행 세션에 전달한다.

후속 작업은 필수 선행 코드가 실제로 준비된 기준에서 시작해야 한다. 원본을 보존한 재현 가능한 스냅샷·패치와 검증 근거를 전달한다. Jira·goal 상태만으로 코드 전달을 대신하지 않는다. 앞 작업의 구현·필수 검증과 코드 인계가 끝났다면, 별도로 남은 사용자 인수·릴리스 승인은 실제 구현 의존성이 없는 한 후속 작업을 막지 않는다.

### 독립 세션 실행과 확인

- **하위 이슈마다 별개의 최상위 세션**을 사용한다. child/subagent·기존 대화의 fork·현재 세션의 일괄 구현으로 대체하지 않는다. 각 세션의 주 에이전트가 그 이슈의 Main이며 구현 스킬의 독립 리뷰어와 Implementer·Tester를 직접 호출하고 역할별 권한과 업무를 유지한다.
- [세션 업무 지시](references/session-prompt.md)에 대상·저장소·기준 명세를 넣고 필요한 선행 결과·사용자 제약을 전달한다. 각 세션은 위 실행 문장 전체를 **실제 goal objective**로 등록하고 수행해야 한다.
- 현재 도구에서 독립 세션 생성·goal·실행·결과 조회 기능을 확인한다. 네이티브 기능이 없을 때만 [Codex 독립 세션 연결](references/independent-sessions.md)을 사용한다. 기능을 제공할 수 없으면 준비한 입력과 제약을 보고한다.
- 생성된 세션의 독립성, 실제 goal과 실행 시작을 각각 확인하고 이슈 Key와 세션 ID의 대응을 보존한다. 생성·전송 응답이 불명확하면 기존 세션·goal·실행 상태를 조회해 같은 실행을 복구한다.
- 본문 순서에 맞춰 준비된 작업만 시작하고, 세션의 실제 결과·검증 근거·코드 인계를 확인하며 다음 작업으로 이어간다. 실패 시 의존하는 후속 작업을 보류하고 나머지도 본문의 순서·병렬 허용 범위를 따른다.

진행 추적은 도구의 대기 기능과 변경분을 우선한다. 새 상태·증거·판단 필요가 없으면 이미 확보한 결과를 재사용하며 같은 조회·재지시·기록 갱신을 반복하지 않는다. 필요한 의존성 판단·장애 복구·최종 증거 확인은 수행한다.

### 상태와 완료

하위 세션은 자기 티켓의 `jira:status`를, 현재 조정 세션은 에픽의 `jira:status`를 담당한다. 에픽 착수는 첫 하위 작업의 착수와 맞춘다. 순서 누락·실행 기능 부재처럼 조정 단계가 막히면 에픽에 반영하며, 아직 시작하지 않은 하위 티켓까지 일괄 갱신하지 않는다.

goal 완료와 Jira 완료는 구분한다. 사용자 인수가 남으면 개발 goal이 완료되어도 Jira는 `검토 중`일 수 있다. 에픽 완료는 주 에이전트가 필수 하위 결과와 전체 완료 조건의 증거로 최종 판단하고 처리하며 자식 goal 완료만으로 결정하지 않는다. 추가 연결 검증이 필요하면 승인 범위와 지정 담당 작업에서 수행한다.

## 결과 반환

실제 Jira 상태·보고 반영, 개발·검증 결과와 남은 항목, 작업 공간·브랜치·결과 참조와 보고서 링크를 반환한다. 에픽은 하위 Key별 세션·goal 결과, 실행 순서와 선행 코드 전달 결과를 함께 요약한다. 시작만 확인했다면 시작 사실까지만 보고한다. 적용되는 전역 goal 완료 보고 절차를 따르며, 보고서 배포 실패는 개발 완료와 구분한다.
