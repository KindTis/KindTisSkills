# 단일 Jira 이슈 작업 실행

단일 이슈의 명세·저장소를 확인하고 다음 지시로 구현한다.

> 첨부된 명세를 $improve:implement 스킬 지침에 따라 작업한다. 작업은 지시한 작업 공간에서 진행하고, 지시가 없으면 현재 브랜치에서 진행한다

이 스킬은 단일 이슈의 명세 식별·구현·검증을 담당한다. 의존 스킬은 사용하는 단계에서 현재 목록으로 찾아 읽는다. 티켓 등록·단순 조회·명세 설명·스킬 편집 요청에는 개발을 시작하지 않는다.

## 대상과 기준 명세

현재 Jira 도구의 실제 스키마로 대상 Key/URL의 프로젝트·유형·본문·첨부·상태를 확인한다. 대상이 에픽 유형이거나 여러 이슈이면 이 절차는 배정된 단일 개발 이슈만 처리함을 알리고 해당 입력으로 개발을 시작하지 않는다.

- 기준 명세는 Description의 `Specification`이 지정한 첨부 Markdown이다. 누락·동명 중복 등으로 기준이 모호하면 확인하며, 최신 업로드나 본문 요약으로 대체하지 않는다.
- 명시된 저장소를 우선한다. 없으면 **Jira의 프로젝트명(스페이스명)이 Codex의 프로젝트 폴더와 동일**한 경로를 찾고, 후보가 없거나 여러 개일 때만 확인한다.
- 작업 범위와 저장소 지침, 전달받은 선행 코드 기준을 확인한다. 재시도는 같은 이슈의 기존 실행·결과를 이어가며 중복 실행을 만들지 않는다.
- `명세 필요` 상태만으로 개발을 중단하지 않는다. Jira 본문의 `Specification`이 실제 접근 가능한 기준 첨부 명세를 명확히 지정하고 사용자가 그 명세의 구현을 지시했다면 개발을 시작할 수 있다. 실제 기준 명세가 없으면 중단하며, 지정 파일 누락·동명 중복 등으로 기준을 확정할 수 없으면 확인 전까지 개발을 시작하지 않는다.

## 단일 이슈 실행

1. 작업 위치는 사용자가 지시한 작업 공간으로 하고, 지시가 없으면 현재 브랜치로 한다. 계획·코드 변경 전에 작업 위치를 확정하고 기존 사용자 변경을 보존한다. worktree를 지시받았으면 `superpowers:using-git-worktrees`로 확보한다.
2. 실제 goal 실행도 요청됐으면 요청·배정된 단일 이슈의 업무 목표로 등록하거나 일치하는 기존 goal을 사용한다. 그 목표를 구현 스킬 실행 문장으로 바꾸거나 다른 미완료 goal을 덮어쓰지 않는다. 지정 첨부를 불변 입력 명세로 작업 위치에 두고 위 지시로 `improve:implement`를 수행한다.
3. 해당 이슈의 승인 범위 안에서 독립 리뷰·구현·재작업·검증을 위임·조정하고 필수 완료 조건을 확인한다. 역할과 Advisor 호출 조건은 `improve:implement` 지침을 따른다. 같은 범위의 재작업마다 승인을 다시 요구하지 않는다.
4. 개발·검증 결과와 남은 인수 항목, 후속 작업에 필요한 재현 가능한 코드 결과·검증 근거를 반환한다. 범위 변경·작업 간 영향·스스로 해결할 수 없는 장애는 필요한 근거와 판단 쟁점을 알린다.

첨부 원본은 보존하며 구현·검증은 구현 스킬의 절차를 따른다. 명세의 모순·누락으로 진행할 수 없으면 진행 불가 사유·필요한 답변·재개 조건을 알린다. Jira 본문·첨부·분류의 변경이나 main/master 병합·푸시·배포·worktree 정리를 이 실행 지시만으로 추가하지 않는다.

## 결과와 완료 판단

goal 완료와 Jira 완료는 구분한다. 개발 goal이 완료돼도 남은 사용자 인수·리뷰를 결과에 명시한다. 실제 개발·필수 검증·리뷰 결과로 완료를 판단하며 시작만 확인했다면 시작 사실까지만 보고한다.

개발·검증 결과와 남은 항목, 작업 공간·브랜치·코드 결과 참조와 보고서 링크를 반환한다. 적용되는 전역 goal 완료 보고 절차를 따르며 보고서 배포 실패는 개발 완료와 구분한다.
