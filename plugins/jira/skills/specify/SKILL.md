# 티켓 일괄 명세화

**대상 선정 → `jira:spec-ticket`으로 명세 보강 → 준비된 티켓을 `할 일`로 전환**한다. 이 스킬은 일괄 처리와 질문 취합을 담당하며, 상세 명세 작성·첨부·본문 갱신은 `jira:spec-ticket`, 상태·댓글 반영은 `jira:status`를 사용한다. 의존 스킬은 사용하는 단계에서 현재 목록으로 찾아 읽는다.

## 대상 선정

사용자가 지정한 티켓 목록·보드·프로젝트·조회 조건과 프로젝트 지침으로 범위를 정한다. 유일하게 정할 수 없을 때만 확인한다. 현재 Jira 도구의 실제 스키마로 조회하며, 상태 ID·도구명·설치 경로는 고정하지 않는다.

- 기본 대상은 범위 안의 **`명세 필요` 상태** 티켓이다. 열 이름이나 첨부 파일 유무만으로 대상을 판단하지 않는다. 필요한 조회 페이지를 모두 확인하고 Key 중복을 제거한다.
- 에픽 하위를 요청받으면 실제 부모·자식 관계로 조회한다. 에픽 자체는 명시된 대상일 때만 보강한다. 작업 분해나 새 티켓 생성은 하지 않는다.
- `확인 요청` 티켓은 명시적인 재개 요청이나 기존 대화·댓글로 이번 명세 보강의 이어가기임을 확인할 수 있을 때 포함한다. 개발 작업의 확인 요청과 구분한다.
- 그 밖의 상태는 제외하고, 다른 상태까지 보강하라는 명시적 요청은 개별 `spec-ticket` 작업으로 처리하되 이 일괄 흐름의 상태 전환은 적용하지 않는다.

대상 Key 집합을 정한 뒤 티켓별 본문·첨부·현재 상태와 필요한 프로젝트 컨텍스트를 확인한다. 공통 컨텍스트는 재사용한다. 대상이 없으면 그 결과를 알리고 종료한다.

## 명세 보강

각 기존 Key, 원래 아이디어, 관련 컨텍스트와 확인된 요구를 `jira:spec-ticket`에 전달한다. 그 스킬이 사용하는 Superpowers 절차로 명세를 작성·검토하며 별도 명세 형식은 만들지 않는다.

기존 명세의 식별·재사용·참조 복구도 `spec-ticket`에 맡긴다. 첨부는 있지만 본문 참조만 없거나, 완성된 명세가 이미 있는 티켓을 무조건 다시 작성하지 않는다. 명세가 준비된 티켓은 검증 결과를 재사용한다.

공통 질문은 묶어서 확인하고, 개별 질문에는 대상 Key를 붙인다. 명세 작성 절차가 요구하는 접근 선택과 명세 승인도 같은 방식으로 취합해 한 번에 묻는다. 원래 요구와 새 제안을 구분하며 핵심 미확정 사항을 임의로 확정하지 않는다. 답변이 필요한 티켓만 보류하고 나머지는 계속 처리한다. 공유 결정에 의존하는 티켓은 함께 보류한다.

## 상태 반영

명세 준비 단계와 확인·완료 사실을 `jira:status`에 전달한다. `명세 필요`와 `할 일`의 상태 범주는 **할 일(To Do)**이다. 실제 상태·전환을 확인하며 지원되지 않으면 워크플로를 바꾸지 않고 미반영을 보고한다.

| 명세 보강 결과 | 상태 |
| --- | --- |
| 명세 작성·검토 중, 아직 미확정 | `명세 필요` 유지 |
| 답변·승인·외부 조치 없이는 해당 명세를 더 진행할 수 없음 | `확인 요청`과 해당 요청 댓글 |
| 요청 해소 후 추가 명세 작업이 남음 | `명세 필요`로 복귀 |
| 필요한 결정과 명세 승인이 확정되고 `spec-ticket`의 명세·첨부·본문·분류 검증까지 완료 | `할 일`로 전환 |

명세 파일이 생겼다는 이유만으로 준비 완료로 판단하지 않는다. 명세 보강은 개발 착수·구현 후 리뷰·개발 완료가 아니며, 개발 착수·완료 댓글도 생성하지 않는다. 질문이 있어도 해당 티켓의 독립적인 명세 작업을 계속할 수 있으면 `명세 필요`를 유지한다.

갱신 직전에 대상 상태가 여전히 유효한지 확인한다. 다른 작업으로 개발이 시작되었거나 완료된 티켓은 추가 갱신·댓글 없이 제외로 보고한다.

## 이어가기와 결과

티켓별 성공한 명세·첨부·본문 결과를 재사용하고 남은 단계만 복구한다. 상태 전환만 실패했다면 명세를 재작성하거나 중복 첨부하지 않는다. 불명확한 쓰기는 재조회하며, 확인할 수 없으면 해당 쓰기만 보류한다. 원인 변화나 새 근거 없이 같은 실패를 반복하지 않는다. 제품 구현·작업 세션 실행은 시작하지 않는다.

결과는 **완료, 확인 필요, 실패·미확인, 제외**로 묶어 Key·링크와 이유를 간결히 반환한다. 완료 항목에는 실제 첨부 파일명과 상태를 포함한다. 여기서 완료는 명세 보강과 `할 일` 전환의 완료이며, 티켓의 개발 완료를 뜻하지 않는다.
