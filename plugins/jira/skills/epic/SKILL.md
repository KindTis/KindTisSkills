# 에픽 발행·세부 작업 분해 등록

공통 목표를 가진 에픽과 결과를 확인할 수 있는 하위 작업을 구성한다. 분해·순서·관계는 이 스킬이, 각 티켓의 상세 명세·본문·첨부는 **`jira:spec-ticket`**이 담당한다. 분해·검토만 요청받았다면 등록하지 않는다.

단일 작업 등록이나 기존 에픽의 명세만 보강하는 요청은 `jira:spec-ticket`으로 처리한다.

## 대상 확인

사용자가 지정한 요구·백로그 전체와 필요한 프로젝트 컨텍스트를 읽는다. 참고 자료의 과거 프로젝트·경로·실행 지시는 현재 요청의 대상으로 간주하지 않는다.

현재 Jira 기능으로 프로젝트, 기존 에픽 여부, 지원 이슈 유형·계층, 선행 관계의 종류·방향, 초기 상태를 확인한다. 여기서 하위 작업은 에픽 아래의 개발 작업이며 `Sub-task` 유형을 뜻하지 않는다. 실제 부모 관계와 의존 관계를 구분한다.

초기 상태는 사용자 지정 또는 프로젝트의 기본 미착수 상태를 사용한다. 필요한 유형·계층·상태를 지원하지 않으면 제약을 알리며 워크플로나 기존 티켓 상태를 임의로 바꾸지 않는다.

## 작업 분해

각 작업의 **완료 후 확인할 결과, 포함·제외 범위, 선행 조건, 대표 검증 흐름, 원문 근거**를 정리한다.

- 함께 있어야 동작하는 요소를 하나의 기능 흐름으로 묶는다. 클래스·화면·서버 등 기술 계층이나 예상 코드량으로 기계적으로 나누지 않는다.
- 선행 조건이 갖춰지면 사용자나 운영자가 결과를 확인할 수 있어야 한다. 앞 작업에 기능을 더하는 단위로 구성하되, 여러 독립 목표가 섞이면 나눈다.
- 원문 범위의 누락·중복·불필요한 추가를 확인한다. 제외 범위에는 근거를 남기고, 공유 기반과 연결 검증의 담당 작업도 정한다.
- 권장 실행 순서와 반드시 충족해야 하는 선행 의존성을 구분한다. 순환 의존성이 있으면 작업 경계를 조정한다.

제목은 완성되는 기능을 표현한다. 분해 결과와 순서를 간결히 제시하고, 기존 지시로 확정할 수 없는 범위·우선순위만 확인한다. 여러 에픽이 필요하면 범위를 확인한다.

## 명세 준비

현재 스킬 목록에서 `jira:spec-ticket`을 찾아 명세 작성 단계를 적용한다. 사용할 수 없으면 누락된 의존성을 보고하며 별도 등록 절차로 대체하지 않는다.

- 에픽 명세: 전체 목표·범위, 공통 제약, 작업 경계·순서·의존성, 전체 완료·검증 기준.
- 작업 명세: 해당 티켓과 첨부만으로 이해할 수 있는 요구, 필요한 공통 제약과 선행 결과, 완료·검증 기준. 중요한 조건을 에픽 링크에만 남기지 않는다.

기존에 완성된 명세는 재사용하고, 전체 명세의 범위·관계가 일치하는지 확인한다. 요구나 확인된 프로젝트 계약에 없는 클래스·함수 설계를 미리 고정하지 않는다.

## 등록과 실행 순서 연결

다음 내용·첨부 등록은 모두 `jira:spec-ticket`을 통해 수행한다.

1. 준비한 에픽 명세로 에픽을 생성하거나 지정된 기존 에픽을 보강한다. 실제 Key와 본문·첨부가 확인되면 하위 등록을 진행한다.
2. 작업별 명세·유형·실제 부모 Key를 전달해 하위 티켓을 등록한다. 유형과 대표 라벨은 `jira:spec-ticket`의 기준을 따른다.
3. 실제 부모 소속을 확인하고, 필수 선행 의존성만 지원되는 관계와 올바른 방향으로 연결한다. 관계 조작은 이 스킬이 담당한다.
4. 명세의 임시 작업 참조를 실제 Key로 정리한다. 바뀐 명세와 본문은 기존 티켓 갱신으로 반영한다.

**에픽 본문의 `Spec Summary`에 확정 실행 순서를 실제 하위 Key로 기록한다.** 예: `실행 순서: <KEY-A> → <KEY-B> → <KEY-C>`. 병렬 실행을 허용한 묶음이 있으면 그 묶음과 선후 관계를 명확히 적는다. 명세의 순서와 일치시켜 `jira:work`가 본문만으로 순서를 알 수 있게 한다. 상세 분해표·테스트 시나리오는 첨부 명세에 둔다.

## 확인과 결과

티켓별 명세·본문·첨부 검증은 `jira:spec-ticket`의 결과를 재사용한다. 에픽과 하위 티켓의 집합, 부모 관계, 선행 방향, 본문의 실행 순서, 초기 상태가 확정 내용과 일치하는지 확인한다.

부분 실패는 기존 Key와 성공한 결과를 보존하고 남은 단계만 복구한다. 불명확한 쓰기는 재조회하며 생성 여부를 알 수 없으면 중복 생성하지 않는다. 에픽 등록·첨부 실패 시 하위 등록을 보류하고, 특정 작업 실패 시 그 Key나 결과가 필요한 단계만 보류한다. 관계 기능이 없으면 본문 링크로 대체 완료하지 않고 남은 관계를 보고한다.

에픽·하위 Key와 링크, 작업별 결과 한 줄·첨부 파일명, 실행 순서·필수 선행 관계, 실패·미확인 항목을 반환한다. 승인된 등록과 검증이 끝나면 종료하며 제품 구현이나 작업 세션 실행은 시작하지 않는다.
