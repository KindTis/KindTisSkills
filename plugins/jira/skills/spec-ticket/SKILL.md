# 완성 명세의 신규 티켓 발급

작성된 명세를 검증해 **새 Jira 이슈 발급 → 명세 첨부 → 본문·분류·부모 확인**을 수행한다. 아이디어 구체화·새 명세 작성·기존 이슈 보강·제품 구현은 담당하지 않는다.

## 입력 검증

입력 명세, 신규 발급 승인 범위, 대상 프로젝트·유형·부모를 확인한다. 필요한 현재 도구의 실제 스키마를 사용하고 대상을 유일하게 정할 수 없을 때만 확인한다. [공통 등록 규칙](../../references/spec-registration.md)을 읽고 본문·첨부·분류·보존·검증 규칙을 적용한다.

- 명세가 현재 요청과 일치하고 상세 요구·범위·제약·예외·완료 조건·검증 기준과 필요한 승인이 확정됐는지 확인한다. 검증 결과와 미실행 항목을 구분한다.
- 입력이 미완성이거나 핵심 결정·승인이 없으면 부족한 점과 필요한 결정을 알린다. brainstorming이나 임의 명세 작성으로 채우지 않으며 신규 발급을 시작하지 않는다.
- 기존 Key의 명세 보강은 이 신규 발급 절차의 대상이 아님을 알리고 기존 이슈를 새 이슈로 대체하지 않는다.
- 완성 명세의 파일명·본문 추출은 수행할 수 있지만 요구·설계를 새로 추가하지 않는다. 첨부 기능을 사용할 수 없으면 생성 전에 제약을 반환한다.

## 발급과 결과

공통 규칙의 **신규 발급**과 **저장 검증·부분 실패**를 수행한다. 전달받은 완성 명세·프로젝트·확정 유형·대표 라벨과 지정된 실제 부모 Key를 입력으로 사용한다. 작업 분해·이슈 간 의존 관계 연결은 이 발급 절차의 범위 밖이다.

생성된 Key와 성공한 결과를 재사용해 남은 단계만 복구한다. Key·링크, 유형·대표 라벨·부모, 명세 경로·실제 첨부 파일명, 검증 결과와 실패·미확인 항목을 반환한다. 발급이 끝나면 종료하며 개발을 시작하지 않는다.
