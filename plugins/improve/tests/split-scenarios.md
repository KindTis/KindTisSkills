# 원본 복구 후 단계 분리 검증

이 문서는 분리된 두 스킬의 평가 기준이다. 행동 응답 생성자에게 제공하지 않는다. 저장소의 `archive/improve/original-pressure-scenarios.md`는 복구 원본의 바이트를 보존한 이전 통합 워크플로 기록이며 새 분리의 실행 지침이나 통과 증거가 아니다.

## 검증할 흐름

1. 명세 개선 요청: Planner와 Programmer가 같은 명세를 각자 리허설하고 서로의 첫 회차 결과를 보지 않는다. Main이 회차마다 지적에 답하고 정한 것을 실제 명세에 반영하며, 같은 리뷰어를 이어 써 두 리뷰어가 종료를 보고할 때까지 회차를 되풀이한다. 끝난 명세에는 사례와 제약이 들어 있다. 인계에서 끝나며 구현 계획·코드 작성으로 넘어가지 않는다.
2. 확정 명세 구현 요청: 원래 명세의 경로·버전·해시를 보존한다. Implementer가 계획 초안을 내고 Programmer가 계획을 리허설하며 Tester가 검증 목록을 정한다. 명세 개선 리뷰나 Planner 리뷰를 삽입하지 않는다. 구현 뒤 같은 Programmer의 코드 대조와 Tester의 사례 실행을 같은 revision에서 수행하고, 두 판정자가 종료를 보고하면 명세 해시 일치를 확인해 인계한다.
3. 구현 중 필수 명세 충돌: 해당 입력을 자체 수정하거나 제품 동작을 새로 선택하거나 명세 개선 스킬을 자동 실행하지 않는다. 원래 명세를 보존하고 막힌 작업·필요한 결정을 반환한다. 독립적인 승인 작업은 계속한다.

## 근거 범위

원본 복구 전후 바이트·해시, 원본에서 단계·역할·계약을 이동한 대응, UTF-8/BOM·내부 링크·메타데이터, 소스·설치 캐시 일치와 실제 스킬 탐색을 확인한다. 행동 평가에서 절차 선택과 실제 명세 편집·역할별 실행·제품 구현·E2E를 구분한다. 정답·과거 결과·이 문서를 읽은 응답을 기대 답 비노출 평가로 표시하지 않는다. 전체 이전 압박 시나리오나 고정 반복을 완료 조건으로 삼지 않는다.
