# 구현 판단과 입력 문제

주 에이전트는 불변 명세와 프로젝트 규칙, 기존 구현·도구 근거, 정확성·안전·호환성, 승인 범위 내 가역적이고 검증 가능한 선택을 기준으로 구현 방식과 계획을 판단한다. 저장소에서 확인 가능한 사실은 직접 조사한다. 리뷰어는 질문·선택지·추천·근거·영향 작업을 부모에게 반환한다.

Main은 구현 계획·진행 기록을 직접 작성·수정하고 구현 작업을 지시한다. 명세 자체의 작성·수정과 제품 요구의 재결정은 이 스킬의 작업이 아니다. 명세를 충족하는 기술 선택·리팩터링은 담당자가 승인 목표 안에서 자율적으로 수행한다.

새 설계·중요한 구조 결정, Main이 근거로 해결하기 어려운 충돌, 조사 결과 요구 재해석이 필요한 쟁점만 Advisor에게 자문한다. Advisor는 읽기 전용으로 선택지·영향·추천을 부모에게 반환하며 파일 수정·자식 생성·담당자 직접 지시·최종 승인을 하지 않는다. 매 착수·일반 실패·모든 리뷰 조정·최종 완료의 필수 호출이나 일상적인 테스트 지휘를 맡기지 않는다.

`MAIN_DECISION`에는 선택지·선택한 답·이유·영향 작업·중요한 가정을 기록한다. 판단 권한이 새로운 기능·수정·외부 행위에 대한 실행 권한을 늘리지는 않는다. 명세의 모순·필수 입력 누락으로 구현을 정할 수 없다면 원문 위치·관측 근거·막힌 작업·필요한 결정을 반환하고 그 부분을 보류한다. 명세나 해시를 바꾸거나 명세 개선 스킬을 자동 실행해 해결하지 않는다. 독립적인 승인 작업은 계속한다.

필수 입력을 찾거나 명세를 보존한 채 합리적으로 정할 수 없거나, 승인되지 않은 범위 확대·불가역/파괴적 행위·외부 권한이 실제로 필요한 경우에만 사용자에게 해당 경계를 묻는다. 계획·구현의 일상 선택이나 이후 출시 승인 때문에 작업을 강제 대기시키지 않는다.

중요한 미결 질문이나 반영 확인이 남아 있으면 부모에게 반환한다. 지적이 해결·근거 있는 거절·명시적 범위 밖 처리로 정리됐다면 검토를 종료한다. 의미 있는 새 질문·수정·증거 없이 검토를 반복하지 않는다.
