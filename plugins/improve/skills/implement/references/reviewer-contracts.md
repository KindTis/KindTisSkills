# 역할별 위임 계약

모델·추론 수준과 공통 위임 경계는 [공유 역할](../../../references/roles-and-dispatch.md)을 따른다. 현재 단계의 계약만 전달하며 자식은 명시적 재위임 허가 없이 에이전트를 만들지 않는다. 리뷰어는 파일을 수정하거나 사용자에게 직접 질문하지 않는다.

입력 명세의 경로·버전·해시를 모든 역할에 전달한다. 이 스킬의 어느 역할도 명세를 작성·수정하지 않는다.

## Common inputs and output

각 위임에 필요한 입력:

- 역할과 요청 모델·추론 수준, 프로젝트·스킬 경로, 적용 규칙과 사용자 승인 범위.
- 정본 명세 경로·불변 스냅샷, 관련 요구 ID, 관련 저장소 파일과 기존 동작 근거.
- 맡은 작업과 제외 범위, 완료 기준, 필요한 환경·검증 명령.
- 후속 작업이면 앞선 결정·변경부·관련 증거·미결 사항. 없는 상태를 임의로 해결됐다고 가정하지 않는다.

리뷰 응답은 검토한 스냅샷·범위, 중요한 지적과 근거·영향·추천·관련 요구, 부모가 정할 결정·미결 질문을 담는다. `BLOCKER`/`MAJOR`/`MINOR`는 영향에 따라 표시한다. 필요할 때 `MAIN_CAN_RESOLVE`, `MAIN_DECISION_REQUIRED`, `EXTERNAL_AUTHORITY_REQUIRED`로 경계를 구분한다. 이름이나 문답 양식을 기계적으로 맞추는 것보다 판단 가능한 내용이 중요하다.

후속 응답은 이전 지적 식별자, Main 결정, 반영된 변경과 해결 여부를 연결한다. 의미 있는 미결 질문·변경·새 증거가 없으면 검토를 닫는다.

## Programmer plan reviewer

**프로필:** 새 독립 Programmer 리뷰어. 주 에이전트가 구현 계획서를 작성한 뒤 검토하며, 계획 작성자나 명세 리뷰의 결과로 이 독립 계획 리뷰를 대신하지 않는다.

**추가 입력:** 정본 명세 버전, 최종 계획 경로·내용 또는 plan-only diff, 요구→작업→검증 대응, 기존 구현 근거, Main 결정·필요한 설계 자문·변경부.

**범위:** 불변 명세를 기준으로 계획의 요구 누락·위반, 인터페이스·데이터 흐름·상태·수명·오류 복구, 기술 타당성·플랫폼·성능·호환성, 작업과 검증의 대응을 독립 검토한다. 검토 대상과 수정 대상은 구현 계획이며 명세의 제품 요구를 재평가하거나 수정하지 않는다. 계획에서 요구를 유지하며 제거 가능한 과잉 작업과 구조도 읽기 전용으로 검토한다. 설치된 `ponytail-review`가 있으면 관련 삭제 기준을 plan-only 범위에 적용한다. 없으면 아래 동등 기준을 사용하고 그 스킬을 사용했다고 주장하지 않는다.

**테스트 계획 연계:** 신규 테스트가 있으면 Main은 전역 검증 지침에 따른 작업 단위 Advisor 자문 결과와 기존 테스트·검증 공백·추가안을 연결한다. Programmer는 자문의 재사용·확장·병합 판단이 계획에 반영됐는지와 필수 요구의 검증 누락을 확인한다. 같은 테스트 타당성·중복·병합 판단은 다시 심사하지 않는다. 신규 테스트에 필요한 자문이 없거나 테스트 계획·근거의 변경으로 기존 판단이 유효하지 않으면 영향받은 항목만 Main에게 반환해 기존 자문 절차로 보완한다.

- `delete`: 요청되지 않은 작업·기능.
- `stdlib`/`native`: 동일 요구를 만족하는 표준 라이브러리·플랫폼·프레임워크·엔진 기능으로 대체할 커스텀 작업.
- `yagni`: 현재 요구·소비자로 정당화되지 않은 추측성 추상화나 설정.
- `shrink`: 동일 동작·검증을 유지하면서 줄일 수 있는 작업·구성 요소. 이후 사용자 수용을 구현 완료 gate에 넣었으면 해당 절차·추적성을 인계로 옮기는 것을 제안한다.

**보호:** 명시 동작, 최소 회귀·smoke 검증, 필수 오류·복구, 보안·개인정보·성능·플랫폼 제약, 호환·마이그레이션, 실제 복수 구현·호출자·플랫폼으로 정당화된 구조를 삭제하지 않는다. 줄 수나 추상화 사용 횟수가 삭제 근거를 대신하지 않는다. 우연히 발견한 정확성 결함은 부모에게 별도 보고한다.

**출력:** 지적 ID·작업/절·분류·제안·구체적 대체·보호 범위가 보존되는 근거. 절감은 작업 수나 코드/설정의 추정으로 표시하고 미측정도 허용한다. 유효한 제안이 없으면 `Lean already. Ship.`을 검토 범위와 함께 반환한다.

**후속:** 변경된 계획과 요구→작업→검증 대응을 재검토한다. 미결이 없으면 `PLAN_REVIEW_COMPLETE`를 반환한다. 계획 PASS는 실제 코드 검토를 대신하지 않는다.

## Programmer code reviewer

**프로필:** 새 독립 Programmer 리뷰어. 구현된 task change를 읽기 전용으로 검토한다.

**추가 입력:** 정본 명세·최종 계획·대응, task baseline과 기존 사용자 변경 또는 이전 파일 스냅샷, 현재 revision/hash, task diff와 미추적 신규 파일 전체, 관련 호출처·재사용 기능·실행 증거, 이전 지적·결정·수정.

**범위:** 불변 명세·승인된 계획 대비 정확성·보안·성능·회귀와 아래 단순화 기준을 검토한다. 명세를 수정하거나 명세 개선 리뷰로 전환하지 않는다. task commit, staged/unstaged 변경과 tracking 여부와 무관한 신규 파일을 포함한다. 관련 호출처로 동등성을 확인하되 무관한 기존 사용자 변경과 저장소 전체 부채를 정리하지 않는다. 위 계획 리뷰의 삭제 기준·보호 범위를 실제 코드에 적용한다. 정확성·보안·성능 결함은 별도로 반환하고 단순화 절감에 합산하지 않는다.

**출력:** 비교 기준과 검토 snapshot·변경/신규 파일·호출처, 지적 ID·파일/위치·분류·대체·근거, 누락 증거와 미결 사항. 제안 절감은 추정이며 실제 순절감이 아니다. 근거가 없으면 미측정, 유효한 cut이 없으면 `Lean already. Ship.`으로 표시한다. 최소 삭제량은 없다.

**후속:** Implementer 반영과 Tester 영향 검사 후 변경부와 관련 호출처·증거를 재검토한다. 요청 범위를 검토했고 미결이 없으면 `CODE_REVIEW_COMPLETE`를 반환한다.

## Implementer

**역할:** 확정된 요구·명세·구현 계획에 따른 승인된 코드 구현·수정·리팩터링과 필요한 테스트·에셋·설정·코드 단순화 반영을 의미 있는 작업 단위로 수행한다. 주 에이전트는 구현 계획·진행 기록을 작성·수정하며, 입력 명세는 모든 역할이 불변으로 유지한다.

**입력:** 부모가 전달한 승인된 목표와 파일 범위, Main이 확정한 판단·설계와 필요한 설계 자문 및 해당 명세/계획 snapshot, baseline·기존 사용자 변경, 완료 기준, 필요한 검증·재현 조건, 제외 범위. 불명확한 승인이나 미결 핵심 요구에 의존하는 수정은 시작하지 않는다.

**자율성:** 목표 안에서 정확성·성능·유지보수성에 필요한 기술 선택과 리팩터링을 결정한다. 새로운 설계 판단·범위 확대·외부 권한이 필요하면 영향받는 작업·선택지·증거를 부모에게 반환하고 독립적인 승인 작업은 계속한다. 재위임과 리뷰어 생성은 허용받지 않은 경우 하지 않는다.

**실행:** 필요한 코드 원인 조사·수정은 승인 목표 안에서 자율적으로 수행한다. 관련 실패 재현과 필요한 격리 테스트를 관련 구현 수정 전에 준비한다. 유닛 테스트를 모든 작업의 의례로 만들거나 구현 후 형식적으로 추가하지 않는다. 사용 가능한 executing-plans는 맡은 승인 작업의 helper로만 적용하고 조기 완료·통합 지침은 따르지 않는다. 사용자 파일과 ignore 상태를 보존한다.

**출력:** 부모 주 에이전트에게 구현/미완료 작업, 실제 변경 파일·동작, 중요한 기술 판단·계획 이탈, 직접 수행한 검사 명령·결과·산출물, 실패와 미검증 항목. 본인 검사와 별도 Tester의 독립 검증을 구분한다. 요청 모델·추론 수준과 런타임에서 확인된 값은 각각 표시하고 관측 불가를 추정으로 채우지 않는다.

## Tester

**역할:** 실제 실패 재현·빌드·E2E·회귀 및 필요한 보조 검사와 증거를 담당한다. 제품 소스·에셋·설정을 수정하거나 통과를 위해 검사·완료 기준을 완화하지 않는다. 승인 범위 안의 분리 fixtures·검증 산출물 작성은 가능하다.

**입력:** 목표·완료 기준·관련 요구, 검증 snapshot과 환경, 원래 실패 시나리오, 재현·검사 명령·필수/보조 검사 구분, 기존 실패 증거, 격리 산출물 경로. 필요한 재현·격리 테스트는 관련 구현 수정 전에 준비하도록 부모 주 에이전트와 순서를 맞춘다.

**실행:** E2E를 우선하며 효과에 맞는 규모를 선택한다. 헤드리스·백그라운드·격리 환경과 분리된 데이터·브라우저 프로필을 사용한다. 사용자 GUI 포커스·입력·오디오·알림 영향을 피하고 불가피한 실행은 부모에게 필요성과 영향을 반환한다. 원래 실패 재현 조건과 판정 기준을 유지한다.

**출력:** 부모 주 에이전트에게 환경과 revision/hash, 정확 명령 또는 재현 절차, exit status·가능한 성공/실패 수, 로그·산출물 위치, 확인된 요구/회귀, 실패 조건·원래 기대와 실제 결과, 구현·fixture/검사·환경·설계 문제의 근거 분류, 미실행/미검증 항목과 제약. 정적·빌드·자동 테스트·실제 화면/입력/오디오·외부 서비스 수용을 구분한다. 성공 문구만으로 완료를 주장하지 않는다.

**실패 반환:** 결함을 직접 수정하지 말고 증거를 부모에게 반환한다. 주 에이전트가 증거와 Tester의 근거 분류로 구현 결함이면 Implementer의 원인 조사·수정, fixture/검사 문제면 검사 담당자, 환경·인프라 문제면 안전한 환경 조치 담당자의 작업을 조정한다. 조사 결과 설계 변경·요구 재해석이 필요한 쟁점은 명세를 수정하지 않고 부모에게 필요한 결정을 반환하며, 설계 자문 조건에 해당하면 Advisor에게 자문한다. 구현 계획이나 코드 리뷰가 영향받으면 해당 Programmer에게 변경부를 재검토시킨다. 수정 후 Tester가 영향 검사를 재실행한다. 필수 검증 실패·미실행을 사용자 수용으로 바꾸거나 `Complete`로 표시하지 않는다.
