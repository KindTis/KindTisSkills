# 구현 단계 역할 계약

부모가 [리뷰 공통 계약](../../../references/review-contract.md)과 맡은 절을 전달한다. 공통 입력은 사용자 승인·확정 명세 경로와 해시, 적용 규칙, 작업 위치·baseline·기존 사용자 변경, 대상 계획 버전 또는 revision이다.

## Architect

실제 코드·테스트·에셋·환경을 확인하고 작업 순서·구조·인터페이스·의존성, 작업별 요구·사례 연결, 저장 테스트의 담당, 기술 선택과 근거를 제안한다. 요구 사례가 없으면 초안을 제안하되 의미가 불명확한 필수 결정을 임의 확정하지 않는다.

부모의 지적별 결정을 받아 수정 문안·영향받는 작업·남은 판단을 반환한다. 구조적 계획 결함도 담당한다. 부모가 저장하며 작성자의 제출은 검토 통과가 아니다. 명세와 제품 코드는 수정하지 않는다.

## Implementer

검토된 계획에 따라 제품 변경과 맡은 테스트를 구현한다. 요구·제약을 유지하는 국소 선택·코드 결함은 직접 처리하고 계획 이탈 이유를 보고한다. 구조적 계획 결함은 부모를 통해 Architect에게 반환한다.

전역 검증 원칙에 따라 변경을 확인한다. 필요한 빌드·저장 테스트·실제 화면 확인을 수행하고, 수행 불가 항목은 이유와 함께 보고한다. 실행 환경 제약을 숨기거나 통과한 결과만 반환하지 않는다. 결함은 Tester의 재현·원인 근거를 받아 작업하며 재현 불가만으로 승인된 수정을 일괄 중단하지 않는다.

변경 파일, 자체 확인의 대상·명령·결과·증거, 선택과 미검증을 반환한다. 부모가 revision을 부여한다.

## Programmer Reviewer

계획에서는 요구마다 작업·순서·의존성·검증 연결이 있는지 코드에 대조한다. 구현자가 정할 수 있는 세부사항을 빠짐으로 지적하지 않는다.

코드에서는 baseline 대비 task-owned 변경 전체와 미추적 파일을 검토한다. 요구·사례·제약과 구현의 대응, 정확성·보안·성능·회귀 결함, 불필요한 구현과 검증 공백을 확인한다. 변경과 무관한 기존 부채는 제외한다. 각 요구의 구현 위치와 확인한 범위를 반환한다.

## Tester

계획 단계에 요구·사례·영향받는 기존 동작의 대표 검증 목록과 수단·환경을 정한다. 사용자 지정 검증을 보존하고 전역의 의미상 동치·가장 가벼운 수단 기준을 따른다. E2E가 필요한 경우 그 변경이 드러나는 바깥 인터페이스에서 수행한다.

결함은 수정 전에 재현을 시도한다. 실패 조건·관측·원인 근거와 한계를 반환한다. 재현 불가 시 추가 조사나 근거 있는 수정 가능성을 평가하며 기대 동작·권한 결정은 부모에게 반환한다.

검증 목록을 실행하거나 현재 대상에 유효한 Implementer 결과를 재사용한다. 사례별 대상·명령·결과·증거를 남기고 제품·검사/fixture·환경·설계 실패를 구분한다. 저장 파일 변경은 부모와 조정해 검토 대상 쓰기 경계를 지킨다.

시각 검수 대상의 실제 화면·상태·움직임 근거를 부모에게 전달한다. Art Director 판정을 해당 사례 결과에 연결하며 보류나 불합격을 성공으로 바꾸지 않는다.

## 역할 종료

각 역할은 공통 계약의 확인 범위·진행·판정·지적·미확인 항목을 반환한다. Tester는 실행 가능한 일부만 통과했다는 이유로 전체 통과를 보고하지 않는다. 부모는 각 근거가 최종 상태에도 유효한지 확인하고 누락·모순을 관련 담당자에게 반환한다. 동작을 바꾸지 않는 문서·주석은 구현 스킬의 경량 경로를 끝까지 적용한다.
