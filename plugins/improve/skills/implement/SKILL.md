# 확정 명세 구현·개선

Architect의 계획 검토·개선 후 Implementer가 구현하고, 코드 리뷰·실행 검증·해당 시각 검수와 수정을 반복한다. 최초 구현이나 검사 통과만으로 끝내지 않는다.

## 범위와 입력

사용자 승인 범위와 확정 명세를 확인한다. 명세 경로·버전·해시를 기록하고 불변 입력으로 보존한다. 명세를 바꿔야 하는 문제는 영향과 필요한 결정을 반환하며 어느 역할도 임의로 명세를 고치거나 명세 개선을 시작하지 않는다.

사용자가 지정한 작업 공간, 없으면 현재 공간을 사용한다. baseline·기존 사용자 변경을 구분하고 merge·배포·정리는 승인 범위에서만 한다. 계획만 요청됐으면 계획 인계에서 끝낸다.

준비 때 [위임 계약](../../references/delegation.md), [리뷰 계약](../../references/review-contract.md), [역할 계약](references/reviewer-contracts.md), [기록 계약](references/progress.md)을 읽는다. 적용되는 전역·프로젝트·사용자 지정 검증 요구를 확인해 계획에 반영한다. 검증 수단은 적용 지침을 따르며 E2E를 일괄 추가하지 않는다.

## 계획 개선

1. Architect가 실제 코드에 근거한 작업·순서·의존성·필요한 기술 선택과 검증 준비를 제안한다. 명세 사례가 없으면 요구에서 사례를 제안하고 부모가 선택 근거를 기록한다.
2. 부모가 계획을 저장·버전 부여하고 Programmer Reviewer와 Tester에게 같은 계획을 보낸다. 사례의 전제조건·관측값으로 요구를 판별할 수 있는지와 수단·환경 준비를 검토하고 지적을 반영해 재검토한다. Tester는 실행 가능성이 불확실한 필수 검증을 먼저 식별해 승인 범위에서 환경 기능을 확인한다. 구현 후에만 확인할 수 있는 항목은 확인 시점·조건을 계획에 남긴다.
3. 결함이면 먼저 재현을 시도한다. 재현되지 않으면 원인 근거와 안전한 수정 가능성·검증 한계를 평가한다. 근거가 충분한 승인 범위의 수정은 진행하며 기대 동작·범위·권한의 불명확성만 사용자 결정으로 반환한다.
4. 계획의 요구별 작업·의존성, 검증 목록과 실행 조건을 확인했고 열린 유효 지적·판정 보류가 없으면 구현한다.

동작을 바꾸지 않는 문서·주석만의 작업은 Programmer Reviewer의 diff 검토로 계획·변경·인계를 마치며 Tester 실행을 추가하지 않는다. 프롬프트처럼 문서 자체가 동작을 바꾸면 해당 행동 확인을 준비한다.

## 구현·리뷰·재작업

- Implementer는 검토된 계획을 구현하고 필요한 자체 확인 결과를 반환한다. 부모가 대상 상태를 식별해 코드 리뷰와 검증에 전달한다.
- Programmer Reviewer는 baseline 대비 task-owned 변경 전체와 미추적 신규 파일을 요구·제약에 대조한다. Tester는 필수 사례를 실행하거나 현재 대상에 유효한 기존 증거를 확인해 재사용한다.
- 코드 결함·국소 선택은 Implementer가, 맡은 검사·fixture는 Tester가 수정한다. 구조·의존성에 영향을 주는 계획 결함은 Architect가 수정 문안을 내고 부모가 저장한 뒤 영향받은 계획 검토·검증 목록을 재확인한다.
- 판정자는 지적별 답·수정과 영향받은 범위를 재확인한다. 대상 상태와 쓰기 경계는 위임 계약을 따른다. 같은 지적이 반복되면 판단을 가를 근거 또는 다른 접근을 확보한다.
- 범위·권한·환경 때문에 진행할 수 없는 항목은 확인 시점에 영향받는 검증과 필요한 조치를 사용자에게 알리고 독립적인 승인 작업은 계속한다.

부모는 필수 사례 전체를 현재 근거와 대조해 확인 완료·미실행·근거 부족·실패를 구분한다. 일부 실행 성공이나 담당자의 요약만으로 남은 필수 작업을 확정하지 않는다. 기존 진행 기록에서 변경·새 결과·새 지적의 영향 항목을 갱신하며 별도 최종 감사 단계를 추가하지 않는다.

## 시각 검수

사용자가 시각 요소 생성·변경 작업의 검수를 요구했다면 해당 요소는 반드시 Art Director 검수를 받는다. 부모가 필요성이 낮다고 생략하지 않는다. 별도 지시가 없어도 시각적 완료 기준이나 실제 변경 영향상 독립 품질 판단이 필요하면 적용한다.

부모가 대상 화면·상태, 승인된 참조·방향·필수 요소를 전달한다. Tester가 실제 적용 화면과 필요한 움직임 증거를 확보하고 Art Director가 판정한다. 원본 에셋 검수와 제품 적용 검수를 구분하며, 자료가 부족하면 판정 보류다.

불합격은 요구 충족·시각 품질에 실질적 영향이 있는 문제로 한정한다. 관측 차이와 영향을 설명하고 수정·실제 적용 결과의 재검수를 반복해 합격 후 완료한다. 미미한 픽셀·폰트 차이나 개인 취향은 불합격 사유가 아니다. 합격에 붙은 선택적 의견은 완료를 막지 않는다. 새 아트 방향을 재검수의 필수 기준으로 소급하지 않는다.

## 완료와 인계

부모는 다음을 종합한다.

- 확정 명세의 요구·제약을 충족하고 필수 검증이 통과했다.
- 해당 리뷰어가 맡은 범위를 확인했으며 열린 유효 지적·판정 보류가 없다.
- 코드 검토·검사·시각 판정의 대상과 근거가 최종 변경에도 유효하다.
- 명세 원본 해시가 유지된다.

완료·부분·진행 불가를 구분해 변경 요약, 주요 기술 선택·계획 이탈, 사례별 수단·명령·대상 상태·결과·증거 위치와 재사용 여부, 작업 공간·브랜치를 반환한다. 남은 사용자 인수·선호 확인·출시 승인은 별도로 표시하며 필수 미검증을 이 항목으로 바꿔 완료하지 않는다.
