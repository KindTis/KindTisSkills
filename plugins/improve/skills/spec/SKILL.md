# 명세 리뷰와 개선

## Core contract

사용자가 지정한 명세를 제품 요구의 기준으로 삼는다. 사용자 지시와 전역·프로젝트 규칙이 이 스킬 및 참조 스킬보다 우선한다. 검토 요청이나 스킬 호출만으로 명세·계획·소스 수정이나 구현 권한이 생기지 않는다. 명시적으로 승인된 변경과 필요한 검증은 반복 승인 없이 완료하고, 새 범위나 권한이 필요한 작업만 확인한다.

명세 개선을 요청받으면 주 에이전트가 독립 리뷰 결과를 조정하고 채택한 개선을 실제 명세에 직접 반영한다. 검토만 요청됐으면 파일을 수정하지 않고 결과를 인계한다. 이 스킬의 작업은 명세 리뷰·조정·개선·변경부 재검토까지다. 구현 계획 작성과 제품 구현은 `improve:implement`의 별도 작업이다.

## Roles and dispatch

[공유 역할과 위임](../../references/roles-and-dispatch.md)을 따른다. 명세 리뷰는 기획자(Planner)와 프로그래머(Programmer)의 독립 리뷰다. 두 리뷰어는 같은 불변 스냅샷을 읽고 최초 결과를 서로 보지 않는다. 리뷰어는 읽기 전용이며 정본 명세의 작성·수정은 주 에이전트가 맡는다. 불변 스냅샷은 해당 리뷰 회차의 비교 기준이며, 주 에이전트가 정본 명세를 개선하지 못하게 하는 제한이 아니다.

## Decisions and authority

주 에이전트는 명시 요구와 사용자 의도, 프로젝트 규칙, 기존 동작과 저장소 근거, 정확성·안전·호환성, 승인 범위 내 가역적이고 검증 가능한 선택 순으로 판단한다. 일반적인 제품 선택이나 리뷰어 이견은 선택지·결정·근거·영향 요구를 기록하고 해결한다. 변경량이나 줄 수 자체는 목표가 아니다.

주 에이전트가 판단하고 필요한 담당 작업을 지시한다. 설계 자문 조건에 해당하는 쟁점만 Advisor에게 선택지·영향·추천을 받아 판단한다. 필수 입력을 찾거나 보수적으로 정할 수 없거나, 승인되지 않은 범위 확대·불가역 행위·외부 권한이 실제로 필요한 경우에만 사용자에게 해당 경계를 묻는다. 영향을 받는 구체적 작업과 근거를 밝히고 독립적인 승인 작업은 계속한다.

## Workflow

현재 요구와 변경에 여전히 유효한 리뷰 근거는 재사용한다. 의미 있는 미해결 질문·실제 수정·새 증거로 영향받은 변경부만 후속 검토하고, 새 근거 없이 같은 검토를 반복하지 않는다.

| 단계 | 실행과 완료 기준 |
|---|---|
| `PREPARE` | 승인 범위·관련 규칙·원본 명세·관련 기존 구현을 확인한다. 정본 명세 경로와 불변 스냅샷, 기존 사용자 변경과 완료 기준을 기록한다. 주 에이전트가 새 설계·중요한 구조 결정이 필요한 쟁점만 Advisor에게 자문한다. |
| `REQUIREMENTS_REVIEW` | Planner와 Programmer가 같은 불변 명세 스냅샷을 독립 검토한다. 서로의 최초 결과를 보지 않는다. 제품 가치·동작과 기술 타당성을 함께 확인한다. |
| `SPEC_RECONCILIATION` | 주 에이전트가 독립 리뷰 결과와 중복 지적을 조정한다. 근거로 해결하기 어려운 요구·설계 충돌만 Advisor에게 자문하고 `ACCEPT`, `REJECT`, `MAIN_DECISION`, `DEFER`, `EXTERNAL_AUTHORITY_REQUIRED`와 근거를 기록한다. 승인된 명세 수정은 주 에이전트가 직접 반영한다. 명세 개선이 승인됐다면 제안 목록만 반환하고 끝내지 않는다. 검토만 승인됐으면 수정하지 않고 결과를 인계한다. |
| `CHANGE_REVIEW` | 명세가 바뀌면 Planner·Programmer가 변경부와 영향받은 요구를 각각 재검토한다. 채택 지적의 반영과 새 모순, 중요한 미결 사항을 해결한다. 같은 무변경 범위를 처음부터 다시 검토하지 않는다. |
| `HANDOFF` | 최종 명세 버전·실제 변경·리뷰 결과·남은 결정을 인계한다. 명세 작업만 승인됐으면 여기서 종료한다. 구현도 별도로 승인돼 있으면 확정된 명세를 불변 입력으로 인계하며, 구현 쪽에서 명세 리뷰를 다시 시작하지 않는다. |

명세 검토·개선 결과는 실제 빌드·E2E·화면·입력·오디오 통과가 아니다. 명세 작성 완료에 구현 goal 완료나 Cloudflare 게시를 요구하지 않는다.
