# 질문과 판단

독립 리뷰어는 판단 요청을 부모 주 에이전트에게 반환하고 부모가 근거로 판단하고 설계 자문 조건에 해당하는 쟁점만 별도 Advisor에게 요청한다. 저장소에서 확인할 수 있는 사실은 직접 조사하고 실제 사용자에게 자료 조사나 일상적인 제품 선택을 넘기지 않는다. 추가 조사 인력이 필요하면 부모에게 요청하며 자식 리뷰어가 임의로 재위임하지 않는다.

## 언제 질문하는가

증거로 해결되지 않는 중요한 결정과 실제 의존성을 분리한다. 필요한 경우 결정 트리와 frontier를 사용해 이미 전제 조건이 정해진 질문을 묶고, 다른 미결 답에 의존하는 질문은 그 답 뒤에 검토한다.

질문에는 결정할 내용, 구체적 선택지, 추천과 근거, 영향 요구·작업, 미결 상태가 실제로 막는 부분을 담는다.

## Main 판단과 설계 자문

Main은 승인 범위의 요구·방향·작업 분해·완료 기준, 일상 제품 선택·리뷰 조정과 최종 완료를 판단한다. 새 설계·중요한 구조 결정이 필요한 착수, Main이 근거로 해결하기 어려운 요구·설계 충돌, 조사 결과 설계 변경·요구 재해석이 필요한 쟁점에만 Advisor에게 자문한다. Advisor는 읽기 전용으로 선택지·영향·추천을 부모에게 반환하며 직접 담당자 지시·파일 수정·자식 생성을 하지 않는다. 매 착수·일반 실패·모든 리뷰 조정·최종 완료의 필수 호출이나 최종 승인 게이트는 없다. 전체 테스트 재심사나 일상적인 테스트 방식·규모·재실행을 지휘하지 않는다. 새 설계 쟁점 없는 재호출을 피하고 가능한 기존 Advisor를 재사용한다.

Main은 [판단 기준](../SKILL.md#decisions-and-authority)에 따라 리뷰어 이견과 일상적인 제품 선택을 해결한다.

`MAIN_DECISION`은 호환을 유지한 Main 판단 코드다. 필요한 설계 자문만 해당 결정에 연결한다. 이 기록에는 선택지·선택한 답·이유·영향 요구·중요한 가정을 기록한다. 명세와 명세 검토 진행 기록의 실제 변경은 승인 범위 안에서 주 에이전트가 직접 반영한다. 판단 권한이 새로운 기능·수정·외부 행위에 대한 실행 권한을 늘리지는 않는다.

`EXTERNAL_AUTHORITY_REQUIRED`는 승인되지 않은 범위 확대·불가역/파괴적 행위·외부 권한이나 찾거나 합리적으로 정할 수 없는 필수 입력 때문에 안전하게 진행할 수 없을 때 사용한다. 구체적으로 막힌 작업과 이유를 반환한다. 단순한 선호·리뷰어 이견·나중 출시 승인은 이 경계의 근거가 아니다.

## 후속 검토와 종료

중요한 미결 질문이나 반영 확인이 남아 있으면 부모에게 반환한다. 중요한 위험을 검토했고 지적이 해결·근거 있는 거절·명시적 범위 밖 처리로 정리됐다면 종료한다.

독립적인 승인 작업은 계속할 수 있지만 승인되지 않은 변경이나 미결 핵심 요구에 의존하는 구현을 먼저 시작하지 않는다.
