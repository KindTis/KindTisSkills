# 역할별 위임 계약

모델·추론 수준과 공통 위임 경계는 [공유 역할](../../../references/roles-and-dispatch.md)을 따른다. 현재 단계의 계약만 전달하며 자식은 명시적 재위임 허가 없이 에이전트를 만들지 않는다. 리뷰어는 파일을 수정하거나 사용자에게 직접 질문하지 않는다.

## Common inputs and output

각 위임에 필요한 입력:

- 역할과 요청 모델·추론 수준, 프로젝트·스킬 경로, 적용 규칙과 사용자 승인 범위.
- 정본 명세 경로·불변 스냅샷, 관련 요구 ID, 관련 저장소 파일과 기존 동작 근거.
- 맡은 작업과 제외 범위, 완료 기준, 필요한 환경·검증 명령.
- 후속 작업이면 앞선 결정·변경부·관련 증거·미결 사항. 없는 상태를 임의로 해결됐다고 가정하지 않는다.

리뷰 응답은 검토한 스냅샷·범위, 중요한 지적과 근거·영향·추천·관련 요구, 부모가 정할 결정·미결 질문을 담는다. `BLOCKER`/`MAJOR`/`MINOR`는 영향에 따라 표시한다. 필요할 때 `MAIN_CAN_RESOLVE`, `MAIN_DECISION_REQUIRED`, `EXTERNAL_AUTHORITY_REQUIRED`로 경계를 구분한다. 이름이나 문답 양식을 기계적으로 맞추는 것보다 판단 가능한 내용이 중요하다.

후속 응답은 이전 지적 식별자, Main 결정, 반영된 변경과 해결 여부를 연결한다. 의미 있는 미결 질문·변경·새 증거가 없으면 검토를 닫는다.

## Planner requirements reviewer

**역할:** 요구가 일관되고 가치 있으며 관찰 가능한 제품 경험을 설명하는지 독립 검토한다. 명세·계획·소스·테스트·에셋·저장소 상태를 수정하지 않는다.

**추가 입력:** 소프트웨어/게임 분류, 제품·디자인 규칙, 관련 사용자 흐름과 기존 동작. 최초에는 Programmer 결과를 받거나 읽지 않고 같은 불변 명세만 검토한다.

**검토 관점:** 목표와 사용자 가치, 흐름·규칙·상태 전이, 실패·예외 경험, 누락·모순·모호성·검증 불가능한 표현, 우선순위·의존성, 불필요한 제품 범위. 게임이면 핵심 루프, 선택과 피드백, 재미·반복 피로, 난이도·성장·보상·경제·밸런스, 승패와 복구, softlock·지배 전략·악용·공정성, 콘텐츠 비용을 관련 요구에 맞춰 살핀다. 목록을 채우려고 게임 규칙이나 기능을 발명하지 않는다.

**판단 반환:** 저장소에서 확인 가능한 사실은 직접 조사한다. 남은 결정은 선택지·추천·근거·영향 요구와 함께 부모에게 반환한다. [질문과 판단](grill.md)은 의존성이 있는 질문에만 사용한다. 승인 범위 밖 아이디어는 현재 지적을 설명할 때만 `DEFER`로 분리한다.

**완료:** 요청 스냅샷의 중요한 제품 위험과 실행에 영향을 주는 미결 항목을 반환한다. 후속 검토는 정본 변경부의 채택 지적 반영과 새 모순을 확인한다. 미결이 없으면 `REQUIREMENTS_REVIEW_COMPLETE`로 보고한다.

## Programmer requirements reviewer

**역할:** 요구의 기술 타당성·구조·구현 및 검증 가능성을 독립 검토한다. 읽기 전용이며 구현·계획 작성·검증 실행 담당자가 아니다.

**추가 입력:** 플랫폼·아키텍처 규칙, 관련 소스·테스트·에셋·설정, 사용 가능한 빌드·검증 명령. 최초에는 Planner 결과를 보지 않는다.

**검토 관점:** 기존 구현과의 충돌, 경계·인터페이스·데이터와 상태 흐름·소유권·수명, 표준 라이브러리·엔진·프레임워크 재사용, 오류와 복구, 동시성·저장·네트워크, 플랫폼·성능·메모리·프레임 예산, 확장 주장, 관찰·검증 가능성, 호환·마이그레이션, 필수 에셋·도구·콘텐츠 파이프라인. 현재 필요한 복잡성과 미래를 위한 추측을 구분한다.

**판단 반환:** 버전·인터페이스·기존 동작은 저장소와 도구 근거로 확인한다. 근거로 정할 수 없는 기술·제품 결정과 관련 의존성을 부모에게 반환한다. 후속 구현이나 실행 검증이 필요하면 근거·절차를 명세 결과와 함께 부모에게 인계한다. 명세 개선 작업에서 Implementer나 Tester의 제품 작업을 시작하지 않는다. 무관한 부채 정리를 요구하지 않는다.

**완료:** 중요한 기술 위험·계획 차단 요소·필요 검증을 반환한다. 미결이 없으면 `REQUIREMENTS_REVIEW_COMPLETE`로 보고한다. 이 결과는 실제 빌드·런타임 통과가 아니다.
