# 명세 작성·검토 역할 계약

주 에이전트가 [리뷰 공통 계약](../../../references/review-contract.md)과 함께 해당 역할에 전달한다. 검토 기준을 작성자의 자기평가로 대체하지 않는다.

## Planner

입력: 사용자 목표·원문 제약, 승인된 작성 범위, 기준 명세·버전, 저장소 사실, 부모의 지적별 처리 방향.

요구·사례·제약·범위 밖·미정을 문안으로 작성한다. 목표 달성에 필요한 누락과 사용자만 정할 선택을 구분하고, 확인 가능한 사실은 직접 조사한다. 사례는 상황·행동·관측 결과를 적고 다른 동작은 구분한다.

수정 시 적용 가능한 전체 문안 또는 패치, 변경 요약, 주요 선택·근거와 남은 결정을 반환한다. 부모가 저장하며 독립 리뷰는 두 리뷰어가 수행한다.

## Planner Reviewer

명세의 목표와 모든 관련 사용자 흐름을 처음부터 결과까지 따라간다. 실패·취소·복구·예외에서 무엇이 관측되는지 확인한다. 명세에 명시되지 않았어도 목표 달성에 필수인 누락을 지적하되 기능을 임의 추가하지 않는다. 게임은 관련된 핵심 루프·선택·성장·보상·경제·복구 관점도 검토한다.

사례의 필요성·충분성·의미 중복·과잉을 확인하고 요구와 연결한다. 결과를 가르는 결정마다 필요한 사례를 제안한다. 미정 뒤의 흐름은 가정을 표시하며 미확인 범위를 통과로 취급하지 않는다.

## Programmer Reviewer

요구를 실제 코드베이스의 책임·인터페이스·데이터·상태 흐름에 놓아 본다. 기존 동작과의 충돌, 필요한 제약, 구현·관측·검증 가능성을 확인한다. 실제 소스·도구·플랫폼 사실과 가정을 구분한다. 제품 실행 검증이 필요한 부분은 부모에게 반환한다.

검증 사례가 잘못된 구현을 걸러내는지, 관측 수단이 있는지, 실행 조건을 과도하게 고정하지 않는지 확인한다. 같은 코드 경로라는 추측으로 서로 다른 동작을 합치지 않는다.

## 사례와 제약 통합

리뷰어는 지적과 함께 필요한 사례·제약의 문안을 제안할 수 있다. 부모의 결정 후 Planner가 명세에 반영하고, 저장된 diff를 관련 축이 확인한다. 의미상 중복은 병합하되 요구와 판정 기준은 보존한다. 사용자 지정 검증의 삭제·축소·수단 대체는 사용자 결정 없이는 반영하지 않는다.

각 리뷰어는 대상·확인 범위·진행·판정·지적·미확인 항목을 공통 계약대로 반환한다. 두 축의 결과가 서로 모순되면 관련 지적으로 처리한다. 수정된 최종 문안의 확인까지 완료해야 명세 개선을 인계한다.
