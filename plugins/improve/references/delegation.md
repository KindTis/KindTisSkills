# 위임 공통 계약

improve 스킬이 자식 에이전트에 작업을 맡길 때 적용한다. 각 역할의 수행 방법과 경계는 역할 설정에 있다.

## 역할 분담

- **주 에이전트:** 승인 범위·요구 사항·완료 기준을 정리하고, 필요한 명세·구현 계획·진행 기록을 직접 작성·수정한다. 작업 위임, 사용자 소통과 결과 취합을 담당하며, 실제 결과와 필요한 검증·리뷰 근거로 최종 완료를 판단한다.
- **Implementer(`implementer`):** 제품 코드·에셋·설정의 구현·수정·리팩터링을 맡는다. 테스트 작성은 작업마다 Implementer와 Tester 중 담당을 정해 전달한다.
- **Tester(`tester`):** Implementer와 독립적으로 정해진 검증 범위와 기준에 따라 검증한다. 같은 revision에서 재현 가능한 Implementer 검사 결과(명령·종료 코드)는 재사용하고 E2E와 남은 공백을 검증한다. 완료 판정의 검증 근거는 Tester의 결과와 Tester가 확인해 재사용한 결과로 한다.
- **Art Director(`art_director`):** 사용자가 시각 검수를 요청하거나 승인된 시각적 완료 기준·아트 방향에 독립적인 판단이 필요할 때 검수·자문한다.
- **Advisor(`advisor`):** 아래 자문 조건에 해당할 때 자문한다.

## Advisor 자문 조건

다음 경우 원래 요청·승인 범위·완료 기준, 관련 근거와 남은 판단 쟁점을 전달해 자문한다.

- 중요한 구조 결정이나, 주 에이전트가 근거로 해결하지 못한 요구·설계·범위 판단.
- 새 테스트 추가나 새 검증 환경(작업 공간 복사 등) 구성: 작업 단위로 필요성과 기존 테스트·환경의 재사용·확장·병합 가능성.
- 근거 있는 서로 다른 시도에도 실패 원인을 좁히지 못할 때.

새로운 판단 쟁점이나 근거가 없으면 기존 자문을 재사용하고, 추가 자문은 가능한 기존 Advisor에게 요청한다.

## 위임 경계

- 위임은 작업 단위로 묶고 필요한 맥락·승인 범위·요구 사항·완료 기준을 전달한다. 등록된 역할을 사용하며 모델·추론 수준과 역할별 수행 방법은 역할 설정을 따르고 위임 요청에서 바꾸지 않는다. 부모 모델·전체 기록을 강제 상속하는 fork 대신 새 맥락이나 필요한 일부 맥락으로 생성한다.
- 자식 에이전트의 생성·호출은 주 에이전트가 담당하며, 재위임은 주 에이전트가 명시적으로 허용한 경우에만 한다.
- 자식 에이전트는 작업 단위의 결과와 추가 판단이 필요한 쟁점을 주 에이전트에게 반환한다. Advisor 자문·사용자 질문·승인이 필요하면 필요성과 근거를 주 에이전트에게 반환한다.
- 자식 에이전트에 위임할 수 없으면 그 사실과 영향받는 작업을 사용자에게 알리고, 해당 작업을 직접 수행할지 확인을 받는다. 그와 무관한 승인 작업은 계속한다.
