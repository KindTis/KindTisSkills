# 리뷰·지적·종료 공통 계약

spec·implement의 주 에이전트와 판정자가 읽는다. 역할의 권한은 역할 설정을, 검증 수단은 전역 AGENTS.md를 따른다.

## 유효한 지적

목표·요구·제약에 연결되고 실제 영향을 설명할 수 있는 문제다. 지적에는 ID, 대상 위치, 연결된 요구나 기준, 문제와 영향, 근거 또는 확인할 사항, 권장 수정 방향을 포함한다. 의심은 확정 결함과 구분하며 조사 없이 수정 의무로 바꾸지 않는다. 권장안과 다른 해결도 문제가 해소되면 인정한다.

| 단계 | 다룰 문제 | 완료를 막지 않는 제안 |
|---|---|---|
| 명세 | 목표에 필요한 누락·모순, 결과가 달라지는 모호함, 구현·판정 불가능성, 불필요한 범위 | 목표와 무관한 기능, 의미가 같은 표현 |
| 계획 | 요구 누락, 의존 순서·기존 구조 충돌, 검증 공백, 불필요한 작업 | 실제 요구·소비자가 없는 미래 설계 |
| 코드 | 요구·제약 위반, 정확성·회귀 결함, 오류 처리 누락, 불필요한 구현·복잡성 | 개인 코딩 취향, 무관한 기존 부채 |
| 시각 결과 | 요구 충족·시각 품질에 실질적 영향을 주는 차이 | 영향이 미미한 픽셀·폰트 차이, 개인 취향·새 아트 방향 |

명세에 없는 결정은 사용자 흐름·구현·판정의 결과를 갈라놓는 경우에 다룬다. 요구를 유지하는 구현 세부사항까지 명세에서 고정하지 않는다. 작다는 이유로 유효한 지적을 제외하지 않되 시각 검수에는 실질적 영향 기준을 적용한다.

## 처리 책임과 상태

주 에이전트는 중복 지적을 통합하고 처리 방향·출처·근거를 기록한다. 작성·구현 담당이 수정하고, 지적을 낸 판정자가 수정 결과나 반증을 확인한다. 여러 축의 중복 지적은 같은 답을 전달하되 각 축의 확인을 보존한다.

- 열림: 조사·판단·수정이 필요하다.
- 재확인 대기: 수정 또는 반증을 제출했다.
- 해소: 판정자가 수정 결과 또는 반증을 확인했다.
- 범위 밖 제안: 현재 완료 조건에 해당하지 않는다는 근거를 남겼다.
- 진행 불가: 필요한 사용자 결정·권한·환경이 없다.

답변이나 설계 결정만으로 해소 처리하지 않는다. 필수 실패를 선택적 개선으로 재분류하거나 진행 불가를 해소로 표시하지 않는다.

## 이견·반복

근거의 순서는 사용자 지시·확정 요구, 저장소·실행·참조 자료의 사실, 에이전트 추천이다. 사실과 요구 해석이 갈리면 차이를 특정하고 판별할 조사·재현·비교를 수행한다. 근거가 부족하면 판정 보류로 남긴다. 같은 주장·실행을 변화 없이 반복하지 않는다.

복수의 타당한 설계 중 선택이면 부모가 필요시 Advisor의 자문을 받아 결정한다. Advisor의 추천 자체로 결함이나 필수 실패가 사라지지 않는다. 선택의 반영과 관련 지적 해소를 확인한다. 사용자 요구·승인 변경, 사용자 지정 검증 축소·대체가 필요하면 사용자에게 반환하고 독립적인 승인 작업은 계속한다.

유효한 결함과 필수 검증 공백을 처리하고, 판정자는 수정·반증 또는 대체 근거가 원래 요구와 확인된 문제를 해소하는지 확인한다. 새 지적도 요구·영향 근거가 있어야 하며 이미 해소한 것은 새 근거가 있을 때만 다시 연다.

## 반환과 종료

판정자는 다음을 함께 반환한다.

- 대상 버전·revision과 실제 확인한 범위.
- 검토 진행: 종료 또는 미완료.
- 판정: 통과, 수정 필요, 판정 보류.
- 지적별 상태·근거, 확인하지 못한 항목.
- 실행 검증이면 사례별 수단·명령·결과·증거 위치와 재사용 여부.

맡은 범위를 확인하고 열린 유효 지적·재확인 대기·진행 불가·판정 보류 항목이 없을 때 통과다. 열람 실패나 일부 검사만 수행한 결과를 지적 없음으로 처리하지 않는다. 검토만 요청이면 범위 내 결과를 인계하고 수정 반복을 시작하지 않는다.

주 에이전트는 최종 대상에 유효한 판정과 필수 증거를 종합해 전체 완료를 판단한다. 필요한 근거가 없는 부분은 부분·진행 불가로 구분하며 사용자 인수 항목으로 바꿔 완료하지 않는다.
