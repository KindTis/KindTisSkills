# 공유 역할과 위임

## Roles and dispatch

| 역할 | 모델 | reasoning effort | 책임 |
|---|---|---|---|
| Main (주 에이전트) | `gpt-6.1-sol` | `xhigh` | 명세 개선에서 요구·제품 선택·명세 작성·수정, 구현에서 불변 명세에 따른 작업 분해·구현 계획/진행 기록 작성·수정·완료 기준 확인·리뷰 조정·일반 실패 분류·직접 위임·사용자 소통·결과 취합·재작업 조정·최종 완료 판단과 처리 |
| Advisor | `gpt-6-astra` | `xhigh` | 새 설계·중요한 구조 결정, Main이 해결하기 어려운 요구·설계 충돌, 조사 결과 설계 변경·요구 재해석의 쟁점만 읽기 전용 자문 |
| Planner | `gpt-6-astra` | `xhigh` | 명세 개선의 독립 요구·제품성 검토 |
| Programmer | `gpt-6-astra` | `xhigh` | 명세 개선의 독립 기술 검토, 구현 계획 독립 리뷰, 실제 코드 독립 리뷰·단순화 검토 |
| Implementer | `gpt-6.1-sol` | `high` | 확정된 명세·구현 계획에 따른 승인된 코드 구현·수정·리팩터링, 필요한 테스트·에셋·설정 반영과 자체 확인 |
| Tester | `gpt-6.1-sol` | `medium` | 실패 재현·빌드·E2E·회귀 실행과 증거 반환 |

역할·모델·추론 수준은 이 표를 기준으로 사용한다. 명세 리뷰는 기획자(Planner)·프로그래머(Programmer)가 독립 수행한다. 구현 계획 리뷰와 코드 리뷰는 각각 새 독립 Programmer가 수행한다. 리뷰어는 읽기 전용이며 각 진입 스킬의 단계와 계약에 해당하는 역할만 사용한다.

모든 자식은 주 에이전트가 직접 생성·호출한다. 자식은 부모의 명시적 재위임 요청 없이는 추가 에이전트를 만들지 않는다. Advisor는 파일 수정·자식 생성·담당자 직접 지시를 하지 않는다. 결과 경로는 자식→부모→필요시 Advisor→부모→담당자다. 주 에이전트는 새 설계·중요한 구조 결정이 필요한 착수, Main이 근거로 해결하기 어려운 요구·설계 충돌, 조사 결과 설계 변경·요구 재해석이 필요한 쟁점에만 Advisor를 호출한다. 매 착수·모든 리뷰 조정·실패 자체·일반 환경 오류·명확한 구현 결함·최종 완료는 필수 호출 조건이 아니다. 전체 테스트 재심사나 일상적인 테스트 방식·규모·재실행 지휘를 맡기지 않는다. 새 설계 쟁점 없는 재호출은 하지 않고 가능한 기존 Advisor를 재사용한다. 간단한 질문·설명이나 짧은 자료 확인은 주 에이전트가 Advisor 호출 없이 직접 처리한다. 도구가 역할 선택을 지원하고 등록된 `advisor`/`implementer`/`tester` 커스텀 역할이 있으면 사용하며 표의 설정과 일치하는지 확인한다. Planner/Programmer 역할이 등록되어 있다고 가정하지 않는다. 역할 인자가 없으면 표의 모델·추론 수준을 명시하고 해당 역할 계약을 전달한다. 전체 기록 fork가 부모 모델을 강제 상속하면 새 맥락 또는 필요한 일부 맥락을 사용한다.

위임 입력에는 승인 범위, 필요한 규칙·원본·현재 스냅샷, 맡은 작업, 완료 기준과 실패 반환 경계를 포함한다. 묵시적 부모 설정 상속, 최저가 모델 선택, 자동 모델 승급으로 표를 바꾸지 않는다. 지정 모델·추론 수준을 사용할 수 없으면 사실과 영향받는 작업을 보고하고 임의 대체하지 않으며, 독립적인 승인 작업은 계속한다. 요청 설정과 실제 관측 설정을 구분한다.
